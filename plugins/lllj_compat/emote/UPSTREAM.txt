Backend selection (TVPCompositor.cpp)
  The isolated-GL backend rasterizes meshes on the GPU in a private SDL GL
  context and reads the result back for the Layer. It is used on hardware GL;
  a software GL driver (llvmpipe/softpipe/swrast) or a failed self-test
  selects the CPU rasterizer. -lllj_emote=cpu|gl forces either one.

Local changes to upstream files (search for "LLLJ")
  emoteplayer.cpp, emoteplayerclass.cpp
      include "lllj_ncbind.h" instead of "ncbind/ncbind.hpp"
  emotefile.cpp
      stream helper members (ReadBuffer/SetPosition/ReadI32LE/ReadI8LE) ->
      krkrz free functions TJS::TVP*(stream, ...); mechanical rewrite
      parse particle settings: frame content "prt", node "particle*"
  EmoteSWRenderBackend.cpp
      SDL2 renderer-assisted path compiled out unless LLLJ_EMOTE_SDL_RENDERER
      (krkrz has no SDL_Renderer); every mesh takes the CPU rasterizer
  EmoteGLRenderBackend.cpp
      SDL3: the private context is built against the window current on the
      main thread (no SDL_Renderer), keeps the engine's GLES attributes,
      bool MakeCurrent/DestroyContext; restores the swap interval that
      creating the context resets (it disabled the engine's vsync)
  TVPCompositor.cpp
      backend selection above
  emoterunner.cpp  (behaviour fixes, verified against this title's assets)
      - loopTime is the re-entry point after lastTime, not the loop length
        (SD scenes: last=120/loop=60 play the intro once, then loop 60..120;
        loop=last-1 holds the last frame). loopTime==0 behaves as before.
      - an embedded motion under a parameterized node restarts from 0 when the
        variable switches the node's content (eyecatch state 0 -> 1)
      - particle emitters ("particle/point|ellipse|quad" sources): eyecatch
        character card and bubbles, sweat/sparkle effects in SD002/007/101/501
  emoteplayerclass.cpp
      - a parameterized main motion's clock is not clamped at lastTime (its
        frame comes from a variable; the clock drives embedded motions)
      - dropped the "skipToSync TODO" / "stop TODO" log lines: both methods
        are implemented, the messages were stale
