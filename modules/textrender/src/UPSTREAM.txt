textrender.dll (TextRenderBase: layout, kinsoku, ruby, links, per-character
delays and key waits) vendored from krkrsdl3. It replaces the earlier
src/TextRenderBase.cpp (krkr-ns' simplified port), which had no timing:
calcShowCount() always returned every character, so text appeared at once
instead of typing out.

  source:  https://github.com/krkrsdl3/krkrsdl3
           plugins/textrender.cpp
  commit:  ff417d194aa08330e8806431026c4efeb8982ebc (2026-10-31)
  copied:  textrender.cpp, LICENSE.krkrsdl3 (repository LICENSE)

Local changes to textrender.cpp (search for "PORT")
  String model: krkrsdl3's tjs_char is char and its ttstr holds UTF-8; in
      krkrz tjs_char is char16_t and ttstr(const char *) decodes Shift_JIS.
      ttstr(utf8.c_str()) became U16(utf8), x.AsStdString() became U8(x),
      TVP_utf8_to_utf16 became Utf8CharToUnit, and GetProp/SetProp convert the
      (ASCII) member names. TJS_N is redefined to TJS_W in the prefix, so the
      kinsoku tables and other literals are UTF-16.
  Rasterizer: the engine's shared GetCurrentRasterizer() instead of a private
      FreeTypeFontRasterizer (which returns zero extents under krkrz's glyph
      renderer). It is not owned, and other users change its font, so
      AscentForSize applies the font on every call and UpdateRasterizerFont is
      a no-op. Text width still comes from the script's onGetTextWidth first.
  Includes: Platform.h dropped (helpers in the prefix); FontRasterizer.h and
      tvpfontstruc.h instead of FreeTypeFontRasterizer.h.

Behaviour fixes, each measured on the Windows textrender.dll with
tools/textrender_compare.py (y positions and delays now match it; x is not
comparable there because the probe's default face has no metrics under Wine):
  %n ([xr]): n line breaks (krkrsdl3 added one more), and nothing at all
      when the ignore_xr option is set (the backlog sets it; krkrsdl3 read the
      option but never used it). The backlog text sat a line low and long
      entries were shrunk to fit.
  render(): starts on a new line when the current one has characters, so
      consecutive sentences in the message window are separated as in the
      original. A "same" render (bilingual sub-language line) restarts its
      timeline at 0 and types out in parallel; getCharacters() returns the
      characters ordered by delay and calcShowCount() no longer assumes the
      delays are monotonic.
  renderTop/renderBottom: the block top (leading blank lines included) and
      the bottom of the last character (no line spacing, no trailing blank
      lines). valign centre/bottom use the same height.
  renderDelay: total duration (last character's delay plus one character),
      not the per-character delay.
  defaultFace: "normal", as the original reports (krkrsdl3: "user").

Build glue (no upstream equivalent)
  textrender_module.cpp       registers the static plugin "compat_textrender"
                                   (prelude/textrender.tjs maps textrender.dll to it)
  shim/textrender_prefix.h    force-included: names the module
                                   (TVP_PLUGIN_NAME), includes compat/ncbind.h,
                                   the UTF-8/UTF-16 helpers
  compat-core/src/layer.cpp        Layer_FetchImageSize (graph sizes when the
                                   script has no onGetGraphSize)

Checking against the original: tools/textrender_compare.py runs
tools/textrender_probe.tjs in the Windows game under Wine (real textrender.dll)
and in this port, and diffs the logged character positions, delays and key waits.
